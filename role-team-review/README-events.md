# 黎明界事件决策模拟说明

## 1. 数据来源

事件不再以日文攻略表作为唯一事实源。

当前审计页直接读取：

```text
pick/autopcr-android/app/src/main/python/cache/db/202604021043.db
```

中的：

```text
labyrinth_event
labyrinth_event_choice
```

生成 `data.js.eventCatalog`。

当前国服可读库共解析出：

```text
22 个事件状态
41 个可选项
```

包括职能角色池、NORMAL/EXTREME 战斗、石板、迷路、猜拳、宝箱、活动会场、钓鱼、料理与老虎机完整三段事件链。

---

## 2. 职能事件映射

游戏事件文字与角色审计表职阶映射如下：

```text
坦克型   -> 掩护者
治疗型   -> 治疗者
强化型   -> 增幅者
增益型   -> 增益者
减益型   -> 减益者
干扰型   -> 妨碍者
攻击型   -> 攻击者
破防型   -> 破防者
```

例如 `1102` 的：

```text
强化型随机角色×2 + α币200
vs
增益型随机角色×2 + α币200
```

不会按固定优先级决定，而是根据当前已获得角色计算两个池子的**当前边际价值期望**。

每个未获得角色都会使用当前 V2 队伍模型估计加入阵容后的提升；事件池只用于求期望，不把用户评分直接作为最终池子答案。

为了避免几十名候选导致浏览器组合爆炸，事件池估值最多保留当前已有角色中个人搜索优先级最高的 12 人参与边际计算。具体三选一仍使用实时角色选择器的完整逻辑。

---

## 3. 角色奖励类型

当前支持：

```text
指定职阶随机角色×2
随机职阶随机角色×2
随机职阶角色自选×1 / ×2
全角色随机×2～4
全角色自选×1 / ×2
指定角色“纯”加入
```

对于 `×2～4`，数据库没有给出数量概率时，事件模拟器暂按期望数量 `3` 估值，并在页面说明中明确标记。

---

## 4. 遗物奖励如何估值

数据库确认普通遗物的基础结构：

```text
★1 -> 1 印记
★2 -> 2 印记
★3 -> 3 印记
```

同时 `labyrinth_relic.price` 中普通遗物价格为：

```text
★1 1800 α币
★2 2800 α币
★3 3800 α币
```

事件模拟器沿用正式遗物路线：

```text
先补 4 加速
再补 4 会心
再补 4 守备
完成 4/4/4 后集中一个印记冲 15
弱体接近 15 时允许转追弱体
```

因此同一个“随机★2遗物”，在：

```text
加速3 / 会心4 / 守备4
```

时的价值，会高于已经：

```text
加速8 / 会心8 / 守备8
```

但离任何 15 层都很远的情况。

事件效用只是内部排序单位，不是伤害百分比。

---

## 5. α币如何与遗物比较

为了让金币选项能与角色/遗物放在同一排序中，当前使用：

```text
1800 α币 ≈ 当前最需要的一件普通★1遗物的内部效用
```

这是基于数据库中的普通★1遗物价格建立的转换尺度，而不是宣称游戏中所有商店情况下 1800 币都必然等价于一件指定遗物。

## 6. 战斗事件

四档斗技场事件均已加入：

```text
NORMAL 200  vs EXTREME 300
NORMAL 300  vs EXTREME 450
NORMAL 400  vs EXTREME 600
NORMAL 500  vs EXTREME 750
```

当前页面提供：

```text
NORMAL 预计胜率
EXTREME 预计胜率
```

默认只是预览值，用户可以按当前难度/阵容调整。

没有实际敌人战斗模型前，不把 EXTREME 胜率伪装成精确自动预测。

---

## 7. 概率事件

### 石板

已支持：

```text
50% α币1500 / 50% α币2000
50% 随机职阶自选1 / 50% 全角色自选1
50% ★2遗物 / 50% ★3遗物
```

### 迷路

已支持：

```text
固定 α币1000
vs
50% ★1遗物 / 50% 随机职阶随机角色×2
```

### 猜拳

三个选项奖励结构完全相同，因此从策略角度视为等价。

页面只为显示期望值暂按“对方三手等概率”估算，不用这个假设区分石头/剪刀/布。

### 宝箱

已支持：

```text
α币2000
vs
★1～3随机遗物
```

数据库文字未给 ★1/★2/★3 的出现概率，因此暂按三档等权估值，并明确标记为假设。

### 活动会场

已支持：

```text
α币2000
vs
纯加入 + 全角色随机×2～4
```

## 8. 三段连锁事件

### 钓鱼

```text
第1段：50% ★1 + 进入下一段
第2段：25% ★2 + 进入下一段
第3段：10% ★3
```

### 料理

```text
第1段：50% 进入下一段
第2段：直接拿随机职阶随机×2，或 50%继续
第3段：随机职阶自选×2，或 50%全角色自选×2
```

### 老虎机

```text
第1段：50% α币2000并继续
第2段：结束，或 50% α币4000并继续
第3段：结束，或 50% α币8000
```

连锁事件使用递归期望值：

```text
当前选项价值
= 成功概率 × (本段奖励 + 下一段最优选择价值)
+ 失败概率 × 失败补偿
```

用户提供的 β2 版本总结指出失败后获得 `500 α币`，当前模拟器按此规则处理。该补偿并非 `labyrinth_event_choice.description` 每条都直接写出，因此在未来国服版本变化时需要再次验证。

---

## 9. 数据库条件字段

部分选项带：

```text
condition_type = 1
condition_value = 2000 / 4000
```

目前页面会原样显示这些条件，但**没有擅自解释成“当前α币必须达到2000/4000”**。

在确认客户端对 `condition_type=1` 的真实含义之前，自动执行层不能根据这个字段隐藏或点击选项。

---

## 10. Android 自动化安全状态

此前 Android 在 `EVENT_CHOICE` 页面会：

```text
默认点击第一个事件选项
```

这对当前事件体系是不安全的，因为第一个选项可能是：

```text
低价值角色池
低收益金币
NORMAL 而非 EXTREME
提前结束赌博
```

现在已经改成：

```text
识别到 EVENT_CHOICE -> 暂停自动点击
等待事件语义决策
```

同时取消事件 UNKNOWN 页面的盲点循环。

下一步需要识别具体 `event_id / choice_id` 后，才把本页的事件策略接回 Android 自动点击。
