# 黎明界助手

作者：**wbero** · QQ 交流群：**1065226139** · 状态：**测试版本**

面向《公主连结 Re:Dive》国服 Bilibili 客户端的原生 Android 助手，主要提供黎明界刷开局、画面识别、路线执行和队伍策略。

应用使用 Kotlin 与 Jetpack Compose 开发，不依赖 Python 运行时、Chaquopy 或外部业务后端。仓库中的 Python 脚本用于离线数据整理；Debug 版本另提供可选的本地网页诊断面板。

> 当前为测试版本，流程可能卡死、停在未知页面、误识别或误操作，不保证自动完成。仅测试过 **MuMu 模拟器、1920 × 1080 分辨率**，手机及其他环境暂未测试。请留意运行状态，出现异常及时暂停，不建议无人值守运行。

## 使用风险

- 本项目与游戏官方无关。自动操作和非官方接口访问可能带来账号限制或封禁风险，不保证账号安全；使用前请自行确认游戏相关规则。
- 角色选择、商店购买、刷新、战斗及彻底撤退会改变真实游戏状态，可能消耗资源或丢失当前开局。启动前核对账号、策略和撤退选项。
- “已执行”仅表示操作已派发，不代表游戏已完成预期操作。当前角色列表滚动、边界回弹、识别与流程衔接仍可能异常，需要人工接管。
- 请勿公开账号密码、访问令牌、验证码、未脱敏日志或包含个人信息的截图。交流群不是账号托管渠道。

## 功能与边界

| 模块 | 当前能力 | 使用边界 |
| --- | --- | --- |
| 账号与登录 | 多账号管理、原生登录、登录状态与凭据管理 | 验证码由用户手动完成 |
| 黎明界刷开局 | 公会、难度、路线和 Boss 条件配置，保存结构化路线，支持“刷到出” | 属于网络任务；彻底撤退会放弃当前开局，启动前需确认 |
| 黎明界画面自动化 | 入口识别、路线节点定位、角色编组、遗物与商店决策、奖励及结算流程处理 | 依赖截图与无障碍手势，游戏必须保持前台；并非所有环节都无人干预 |
| 队伍编组 | 角色识别、属性筛选、双向滚动查找、普通及 Boss 编组界面适配 | 资料不完整可参与评分；视觉识别不可靠或无法满足 T 站位规则时仍阻塞 |
| 手机端策略设置 | 评分权重、选人部署权重、遗物、商店及事件参数 | 保存后在下一次任务启动时生效 |
| 个人角色评分 | 头像列表、名称/版本/ID 搜索、自定义 0–100 分及恢复原评分 | 不覆盖原始数据库事实，也不补造缺失的属性、职阶和站位 |
| 任务通知 | 状态展示、暂停/继续、停止和返回应用 | 控制信息不再以悬浮窗遮挡游戏 |
| 可可萝会战助手 | 轴校验、画面识别和动作意图预览 | 目前为 Dry Run，只读预览，真实会战点击入口仍关闭 |

### 当前自动编组规则

- 角色资料不完整不再单独禁止自动选人或编组，按已有信息评分并保留提示；属性未知时通过“全部”列表查找。无资料但身份已可靠识别的角色仅建立 ID/名称记录，不编造评分和游戏事实。
- 按数据库站位确定实际一号位，自动战斗阵容硬性要求最前排为 T（掩护者）；没有符合条件的阵容时停止推荐，而不是让高评分输出角色替代 T。
- 重复纯坦、纯治疗仍参与冗余扣分，不等于严格限制“最多一坦一奶”。
- 找不到目标角色时，先回到列表顶部，再逐屏向下查找；到底仍未找到可靠目标时停止。已选成员以下方成员栏的识别结果为准，不把发出点击当成选人成功。
- Boss 支持多队和单队模式，当前默认多队；单队模式下确认第一队并核对第二、三队留空，到第三队页面识别“战斗开始”后开战。重新启动自动编组时请先回到「队伍1」。

这些是项目策略，并非对游戏最优阵容的保证。角色奖励、遗物和编组评分也不等同于实战胜率。

## 运行环境

- 工程最低系统要求为 Android 8.0（API 26），不代表已验证所有符合版本要求的设备。
- 已测试环境仅为 **MuMu 模拟器，1920 × 1080**。手机、其他模拟器、其他分辨率及宽高比均暂未验证。
- 当前适配游戏包名：`com.bilibili.priconne`。
- 视觉资源以横屏 `1920 × 1080` 为主要参考尺寸，识别时进行坐标映射；其他分辨率、宽高比、遮挡和窗口裁切需要实际验证。
- 登录、刷开局和数据库更新需要网络；画面自动化需要通知、屏幕捕获和无障碍服务权限。不需要悬浮窗权限。

“后台运行”指网络刷开局可在离开工具箱页面后继续。画面自动化不能在游戏退到后台、锁屏或被其他应用遮挡后照常操作。

### 手机及其他设备适配

有兴趣的朋友可以自行测试并提交适配配置。请重点检查截图尺寸与显示区域、系统导航栏/刘海遮挡、模板区域、点击和滑动坐标，以及屏幕捕获、无障碍和后台权限；不能仅凭 APK 能安装就视为适配完成。

可参考作者的 [可可萝公会战自动项目](https://github.com/wbero/kokkoro-clan-battle-assistant) 中的实现方式。参考不代表本项目已具备相同设备兼容性。反馈时请附设备型号、Android 版本、分辨率及脱敏后的原始截图，注明改动的配置。

## 开始使用

1. 安装构建出的 APK，进入账号管理，添加并选择账号，按提示完成登录及人工验证码。
2. 在权限中心开启任务所需权限。屏幕捕获授权被撤销或进程重启后，按应用提示重新授权；通知权限和任务通知频道也需开启。
3. 进入黎明界，在「刷开局设置」中配置公会、难度、路线及撤退选项，保存后启动刷取。刷开局配置按账号保存。
4. 在右上角「策略设置」调整评分、个人角色分数、遗物和商店偏好。策略配置为所有账号共用，运行中的任务继续使用启动时的快照。
5. 需要画面自动化时，开启屏幕捕获并让游戏保持前台。建议先检查识别预览，再启动自动执行；通过通知栏暂停或停止任务。
6. 启动「批量自动执行」后，请立即打开或切换到《公主连结》，并让游戏保持前台；不要停留在助手界面，否则无障碍服务无法把后续点击送到游戏。
7. 在游戏的黎明界页面，打开右上角设置并关闭「播放角色加入动画」。关闭后可避免角色加入后的全屏展示页遮挡黎明界 UI，降低路线执行被过场画面打断的概率。

新建刷开局配置默认启用“刷到出”和“允许彻底撤退当前开局”，已有保存配置不会因此强制覆盖。使用前请核对设置，尤其是当前开局是否需要保留。

验证码、部分人工角色选择和无法安全判断的页面仍可能需要接管。当前界面中的多轮自动执行与轮间会话重置仍有限制，不应把单轮执行能力理解为无限循环通关。

## 数据库与资源

项目区分三类数据：

- **国服游戏数据库**：应用启动时在后台检查 `wbero/autopcr-db-builder` 的 Release 清单；版本或哈希变化、本地数据库缺失时下载完整 `.db`。这不是差分更新，文件可能达到数十 MB，实际大小以对应 Release 为准。
- **内置资源包**：位于 `android/app/src/main/assets/resource-packs/cn-bilibili/`，包含角色目录、图标、识别模板、遗物与策略数据。更新游戏数据库不会自动更新所有模板和人工评分。
- **用户配置与运行状态**：保存在设备本地，包括账号关联的刷开局设置、全局策略、个人评分和路线状态。

数据库先下载到临时文件，经过 SHA-256、SQLite 完整性和表结构校验后再安装。网络或候选文件校验失败不会直接用坏文件覆盖当前数据库。启动了检查并不代表已成功更新；出现资料缺失时应同时检查更新日志与内置策略资料。

更新入口见 [AndroidLabyrinthCnDatabaseRepository.kt](android/app/src/main/java/com/landosol/toolbox/labyrinth/AndroidLabyrinthCnDatabaseRepository.kt)。数据库更新完成后，建议停止并重新启动识别任务，以重新加载决策数据。

## 本地开发与构建

### 工具链

使用 JDK 17、Android SDK Platform 35 和项目自带的 Gradle Wrapper。当前工程配置为 Gradle 8.7、Android Gradle Plugin 8.5.2、Kotlin 1.9.24。

可使用 Android Studio 打开 `android/`，完成 SDK 配置；命令行构建前也需配置 SDK 路径，例如通过本机 `android/local.properties`。不要提交该文件、账号凭据或签名密钥。

### Windows / PowerShell

从仓库根目录执行：

```powershell
cd android
.\build-local.ps1
```

默认执行 `lintDebug`、`testDebugUnitTest` 和 `assembleDebug`。脚本会在工作区路径含非 ASCII 字符时临时映射盘符，结束后解除映射。

只构建 APK：

```powershell
.\gradlew.bat :app:assembleDebug
```

如果用户级 Gradle 配置中的代理已失效，可使用：

```powershell
.\build-local.ps1 -IgnoreUserGradleProxy
```

此选项会临时移开整个用户级 `gradle.properties`，不仅是代理字段；脚本结束后恢复，使用时不要并行运行依赖该配置的其他 Gradle 任务。

### Linux / macOS

```sh
cd android
./gradlew lintDebug testDebugUnitTest assembleDebug
```

Debug APK 输出：`android/app/build/outputs/apk/debug/app-debug.apk`。

CI 配置位于 [.github/workflows/android-ci.yml](.github/workflows/android-ci.yml)，执行静态检查、单元测试和 Debug 构建，并上传 APK 构建产物；这不等于自动发布正式版本。

## 测试与诊断

### 本地测试

以下命令均从 `android/` 执行：

```powershell
# JVM 单元测试
.\gradlew.bat :app:testDebugUnitTest

# 在 192 MiB 测试堆限制下验证内存敏感逻辑
.\gradlew.bat -I ../tools/gradle/heap-regression.gradle :app:testDebugUnitTest
```

测试覆盖策略、会话状态、识别、滚动、数据库更新等逻辑。部分历史截图测试依赖未入库的本地素材，缺少时会跳过；单元测试通过不代表真机或模拟器的完整游戏流程已验证。

### 网页诊断面板

Debug 版本提供设备本地回环地址上的 `8765` 端口，可查看原始帧、识别框、当前页面、动作和阶段耗时。打开黎明界识别入口后，可通过 ADB 转发到电脑：

```sh
adb devices
adb forward tcp:8765 tcp:8765
```

然后访问 `http://127.0.0.1:8765/`。连接多个设备时，在命令中增加 `-s 设备序列号`；使用完毕可执行 `adb forward --remove tcp:8765` 取消转发。Release 版本不启用此面板。

诊断页面可能展示游戏画面和账号相关信息，不要将端口公开到互联网；分享截图或日志前先检查并遮盖敏感内容。

### 反馈问题时建议提供

- 所处页面、预期操作、实际现象及可复现步骤。
- App 构建版本、设备/模拟器型号、Android 版本和截图尺寸。
- 原始游戏截图与诊断识别框截图，注明是否为手动裁切或缩放截图。
- 对应错误日志、当前页识别结果及各阶段耗时。

若显示“已执行点击”但游戏没有响应，先检查游戏前台状态和无障碍授权；若画面更新迟缓，区分原始帧、识别帧及网页刷新，避免只凭截图刷新速度判断点击失败。
