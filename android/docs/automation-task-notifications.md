# 自动化信息迁移至通知栏

- 应用改用 AndroidAutomationNotificationHost，展示任务标题、状态、展开后的详细信息，提供暂停/继续、停止和点击返回应用入口。
- 采用低重要度、静默、常驻通知；文本变化时更新，连续识别帧合并处理，最多约每秒刷新一次。详细内容限制长度，完整诊断仍在应用和网页调试面板。
- 不创建控制窗或屏幕标注窗，不消耗游戏区域，不把诊断标签送回截图。识别框仍保留在共享状态和远程面板。
- 删除旧悬浮窗服务注册及 SYSTEM_ALERT_WINDOW 权限，启动流程不再申请该权限。旧绘制源码暂保留，但应用已不再调用或注册该服务。
- 未授权通知时先请求权限；已授权但通知或任务频道被关闭时引导系统通知设置。通知展示失败会回滚任务控制绑定，避免无控制入口运行。
- 通知操作使用不可变的显式 PendingIntent 和非导出 Receiver；同时校验任务 ID 与随机进程标识，防止应用重启后 ID 重用导致旧通知控制新任务。
- 暂停与停止回到原会话处理器，原有捕获租约和任务资源释放机制不变。任务结束取消对应通知；进程被系统终止遗留的通知点击控制按钮后只清除旧通知，不启动任务。
- 保留系统要求的屏幕捕获前台通知和已有网络刷开局通知，不新建前台服务。此改动不代表视觉自动化可以在游戏退到后台后继续点击。

本地验证包含通知内容、模式提示、诊断框隔离、长度上限、跨会话/跨进程动作隔离、权限门槛及通知宿主失败回滚。手机通知展开、按钮和厂商系统显示效果需用户验证。
