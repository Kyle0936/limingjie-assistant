# 节点进入中断恢复

移动确认执行成功时会保存一个原子化确认记录：目标 transition 与原节点 sourceId 放在同一对象中，避免帧线程看到不配对的状态。该记录在同一执行会话内可跨标题、加载、主页和重新进入黎明界保留，最长十分钟。

恢复时必须同时满足：实际页面类型与目标节点类型一致、当前路线仍停在原节点、保存目标仍是路线下一节点，并且协议图确认原节点只有这一个可达后继。多分支节点即使目标类型页面相同，也不会仅凭历史记录推进路线。

满足条件后统一调用现有 `afterClick()` 与路线持久化，并立即消费确认记录。地图重新出现、遗物数量变化、通用奖励页等都不会单独触发推进。完整节点执行状态重置或新会话开始时会清空该记录。

## 无法认领的移动确认弹窗：点击取消（2026-09-15）

### 现象

`limingjie-debug-20260915-203319.zip`：600 帧全部是节点页，313 秒内没有任何节点被识别（`nodeSearchMode=none`，窗口数 0），会话反复以"目标几何应在当前画面但分类缺失"为由左右微调地图，共 78 次。截图显示画面中央一直挂着一个"移动目标确认"弹窗。

### 根因

这是一个双向死锁：

- 帧处理器识别出了弹窗，因此按设计跳过了节点分类。这是正确的，弹窗开着时地图不可点。
- 会话侧没有人接管这一帧。`pendingNodeTransition` 为空，因为弹窗不是程序点出来的。孤儿恢复要求路线图上只有唯一可达后继，日志里可达节点是 `[10301, 10302, 10303]` 三个，无法确定该弹窗对应哪一个，恢复被拒。
- 于是流程掉进节点搜索分支，看到零个分类结果，跟踪器又记得目标列应该在画面内，判定为"可见但识别不到"，开始微调滑动。滑动落在弹窗上，永远关不掉它。

原有设计只覆盖了"能认领"的孤儿弹窗。认领不了的弹窗没有出路。

### 处理

- 检测器额外输出取消按钮矩形 `cancelButtonRect`，参考坐标 (545, 690, 415, 105)，与确认按钮同一行、左侧。
- 会话在孤儿弹窗无法恢复时，改走 `labyrinthShouldDismissOrphanNodeMoveConfirmation` 门：连续 2 帧看到弹窗、最多 3 次、间隔 2 秒，点击取消按钮。取消成功后重置滚图和微调计数，因为它们统计的是被弹窗挡住的画面而不是地图。
- 三次都无效则停在提示"请手动关闭"，不再滑动。
- 该分支直接 `return`，节点搜索不再在弹窗开着时运行。

不走"点弹窗外区域"关闭，因为弹窗外的点击位置不受控，可能落在节点上再次触发弹窗。

### 验证

- 门函数单测覆盖：可恢复时不取消、有待确认时不取消、单帧不取消、三次上限、两秒间隔、非地图页不取消。
- 检测器单测断言取消按钮矩形。
- 真实截图 fixture `event-move-confirmation-20260913.png` 在原生和缩放分辨率下，取消按钮中心落在弹窗左半、与确认按钮同行、右边界不越过确认按钮。
- 实机误触场景尚未用新版本验证。

## 商店退出确认不是孤儿弹窗；节点进入页面误判要多帧确认（2026-09-16）

### 商店退出确认被当成移动确认

"商店确认"弹窗和"移动目标确认"弹窗的结构完全一样：蓝标题栏、白底、左白右蓝两个按钮，颜色检测器分不开。弹窗盖住了商店标题，页面分类退成 UNKNOWN，而 UNKNOWN 又在孤儿弹窗的允许页面集合里，于是会话准备点取消。

处理：孤儿分支增加两个门。一是 `entryPhaseComplete`，入口流程没交接前不进这个分支；二是 `labyrinthShopBackgroundVisible`，商店标题、说明、刷新按钮、关闭按钮四个锚点里有两个以上仍可见时，弹窗归商店处理器，孤儿计数清零并放行到后面的商店流程。这个判断和商店印记加入页复用同一个函数。

### 连结节点第一帧被识别为遗物页

`limingjie-debug-20260915-235518.zip`：点击连结#20602，进入页面第一帧分类为 RELIC_CHOICE（遗物说明模板 0.87，连结说明 1.00，但连结卡片签名只有 0.44，没过排序加权的门槛），下一帧就是 LINK_CHOICE。连结和遗物页共享标题和剩余次数锚点，只靠说明栏几个字和卡片签名区分。

原逻辑在第一帧不匹配就 `finishFromPlanner` 停机，`afterClick` 没跑，路线游标停在 20602 之前。用户重启后接管的是 LINK_CHOICE，程序按游标继续找 20602，而它已经过了。

处理：`confirmPendingNodeTransition` 里类型不匹配改为累计 `nodeEntryMismatchFrames`，连续 3 帧仍不匹配才停机，期间显示"等待后续帧确认"。新建待确认转移时清零。

### 验证

策略层单测覆盖商店背景门。类型不匹配的多帧确认没有帧驱动会话测试，逻辑在代码审查层面确认。实机未验证。
