# 自动执行主流程与辅助工具

## 目标

黎明界首页以日常使用顺序组织，而不是把刷开局、当前开局和自动执行作为三个同级页签：

1. 登录当前助手账号并读取服务器上的当前开局；
2. 配置目标并开始自动执行。

单独刷开局归入辅助工具。只读识别和标准入口执行收进可展开的识别工具。作者、交流群和诊断链接放在页面底部，避免盖过主要任务。

## 登录与读取的含义

“登录并读取”调用 `LabyrinthController.checkStatus()`。如果当前账号没有可用的游戏服会话，它会从账号库读取加密凭据并执行原生登录；登录成功后保存游戏 UID，再读取 `top` 和现有路线。

这只建立助手的网络会话，不会切换模拟器中《公主连结》客户端的登录账号。账号库中的“设为当前”也只切换助手侧账号。用户在多账号环境中仍需保证游戏客户端和助手当前账号一致。

## 当前开局读取边界

读取结果只用于明确展示服务器当前的公会、难度、路线判定和 Enter ID。磁盘中的旧检查点不会自动恢复成一次新的“读取成功”，设置变化后也会要求重新读取，以免把历史记录误当作当前服务端状态。

本 PR 不改变批量开始语义：无论读取结果是否符合路线，自动执行都按首个批量目标重新准备开局。初始开局复用将作为独立功能单独审查；服务端接口无法恢复已在局内获得的角色和遗物，因此不提供中途接管。

## 页面层级

- 顶栏：刷开局设置、策略设置。
- 主流程第 1 步：账号、UID、路线判定、公会、难度、Enter ID 和“登录并读取”。
- 主流程第 2 步：批量目标、计数方式、当前批次进度和主启动按钮。
- 辅助工具：单独刷开局；识别诊断默认折叠。
- 页脚：作者、交流群、实时日志和日志下载。

主要内容使用标题、步骤编号和分隔线建立层级。卡片只保留给确实需要边界的运行消息、弹窗和诊断内容，避免所有文字块拥有相同视觉权重。

## 安全边界

- 读取结果不会跳过刷开局；批量执行每轮都按当前目标重新准备开局。
- 第 1 步使用明确状态：未读取、读取中、等待登录验证、当前无开局、符合目标、不符合目标、待验证、失败或取消；结果与错误直接显示在步骤内，不再把 `routeVerdict == null` 一律描述成“尚未读取”。
- 公会不再属于“刷开局设置”。批量运行始终使用当前活动 `LabyrinthBatchGoal.guildId`；“单独刷开局”在辅助工具里选择本次公会，并只覆盖本次运行快照，不写回账号设置。
- 登录读取、批量执行、单独刷开局和高级识别共用账号会话、检查点与截图租约；界面与应用入口均按互斥任务处理，批量运行期间不会再显示可启动的旁路操作。
- 游戏必须处于前台，屏幕捕获与无障碍服务必须可用。

## 自适应界面

主页按可用宽度而不是固定像素排列。窄屏、分屏或系统放大时，状态与主按钮会改为纵向排列；目标公会输入框与计数方式会换行，无法换行的短选项行允许横向滚动。宽屏保持并排布局。游戏识别仍使用统一的横屏参考坐标，竖屏设备捕获会在进入识别前正规化为横屏，避免 UI 尺寸变化影响游戏点击坐标。
