# 开局多行角色识别修正

## 现象

咲恋救济院开局在「全部」多行列表中多数头像被识别成错误候选；同角色切换属性分类、列表缩为单行后可以识别。最终提示三个初始方案槽位未找到可靠候选，而不是目标实际不在画面。

## 修正

- 完整可见的开局卡片，无论单行或多行，都用检测到的实际边界生成头像裁剪，不再使用邻近的旧固定布局坐标。
- 上下边缘被截断的开局卡片保留原有完整卡片坐标校准；旧坐标匹配不可信时允许以检测框复核。
- 开局复核沿用选中序号、左下角标记、底栏及视口截断的遮罩，属性证据随所用裁剪框重新计算。
- 只有复核候选通过原置信度及跨角色分差门槛才采用。不降低点击阈值、不改公会三人方案、不开放随机补位。
- 战前编组的默认校准策略保持不变。

## 验证

本地回归覆盖完整多行开局的小于四分之一卡片偏移、图案身份识别、单行与战前布局兼容，以及上下截断布局。实际模拟器仍由用户验证，未宣称现场识别已验证成功。

用户验收：用咲恋救济院「全部」页核对头像身份，再对比火/水等单行分类；同时确认美食殿堂原开局及滚动到边缘时没有退化。

## 点击后视口不稳定不算"未观察到选中反馈"（2026-09-15）

### 现象

`limingjie-debug-20260915-224908.zip`：点击初始角色贪吃佩可（夏日）后 3 秒自动停止，理由是"未观察到选中反馈"。但最后一帧截图里那张卡已经带着白色"1"角标，选中成功了。两次尝试都这样。

### 根因

点击本身改变了视口签名：卡片变暗、多了角标。识别器进入 `WAITING_FOR_STABILITY`，这个状态下返回空的角色列表，而不是"该卡未选中"。入口规划器用墙钟计时：3 秒内没在角色列表里看到该 id 被选中就停机。它把"没看到"当成了"看到了没选中"。

慢机器上识别一帧 700 到 1300ms，两帧稳定需要 1.5 到 2.5 秒，加上点击后的动画，3 秒经常不够。

### 处理

规划器只在 `recognitionState == STABLE` 的帧上累计"已检查"次数。停机条件改为：软超时 3 秒已到，且至少 2 个稳定帧都确认该卡未选中。另加 12 秒硬上限，防止视口永远不稳定时挂死。没有视口观测的调用方每帧都算已检查，旧行为不变。

### 验证

两个新单测：盲帧不计数、稳定帧计数到 2 才停；反馈在软超时六倍之后才到达时仍被接受并推进到下一目标；硬上限生效。原有"不重复点击同一目标"测试保留。
