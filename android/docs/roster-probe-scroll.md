# 编组列表自恢复滑动

只要已经确认处于角色编组页，列表滑动就是该页面允许的白名单动作。蓝色滚动条现在只作为边界/位移证据，不再作为“是否允许滑动”的前置条件；即使滚动条未识别、只有一屏甚至只有一个角色，也允许执行上下滑动并利用内容变化或回弹判断结果。

搜索优先回到顶部，再向下遍历。滚动条缺失时，使用稳定且可信的角色 ID + 卡片位置生成可见签名；连续同方向试探后签名不变可辅助确认顶/底边界。空白帧、未稳定帧和未确认角色不会单独证明边界，也不存在“试探六次即停止”的预算。

普通编组与“有效效果”扫描共享这一原则。单轮总滚动仍有 48 次动作上限用于防止失控，但达到上限后会重置搜索并从顶部重新建立扫描，而不是结束整个自动化。动作反馈未确认时丢弃旧执行计划并重新识别当前编组页。

角色点击仍要求稳定页面、可信头像和现有编组计划校验；放宽的是滚动许可，不是角色点击许可。

## 滚动条未测得不等于单页（2026-09-14）

现场日志显示编组页 600 帧全部报告“无需滚动”，自动化在未执行任何滑动的情况下直接宣布“已扫到底仍未识别推荐角色：矛依未”。识别器给出的是 `canScroll=false`、`position=0.0`，搜索把它当作单页直接结束。

搜索侧不再把 `canScroll=false` 当作“已到底”。只有可见、可滚动、位置在 0..1 内的拇指才是边界证据；否则一律进入真实滑动试探，用内容签名的变化或连续两次同向不变来判断边界。滑动后若滚动条仍未测得，但稳定内容已经变化，立即视为滑动生效，不再等满 12 帧。
